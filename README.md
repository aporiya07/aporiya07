## About Me

I'm Ankit Poriya, an AI / LLM Engineer focused on building practical AI systems that combine intelligent agents, language models, software infrastructure, and product engineering.

My work spans the complete AI engineering workflow: experimenting with emerging models, designing agentic architectures, integrating tools and APIs, optimizing inference, and building applications around real-world use cases.

I'm particularly interested in the engineering behind reliable AI systems: how agents coordinate, how models are selected and evaluated, how inference costs can be optimized, and how AI development tools can make software engineering more effective.

- **Personal AI Projects:** Experimenting with emerging models, autonomous assistants, AI-powered utilities, and developer tools.

## Engineering Approach

I care about more than making an AI demo work once.

My engineering approach emphasizes:

- **Reliability:** Input validation, explicit failure handling, retries, and sensible fallbacks.
- **Observability:** Traces, logs, latency measurements, token usage, and error analysis.
- **Evaluation:** Repeatable test cases, baseline comparisons, and evidence-driven improvements.
- **Efficiency:** Model selection, prompt optimization, inference performance, and cost awareness.
- **Maintainability:** Modular architecture, clear interfaces, automated tests, and useful documentation.
- **Reproducibility:** Documented environments, configuration examples, and repeatable experiments.

## Architecture & Technical Experiments

I use architecture diagrams, reproducible experiments, and benchmarks to understand how AI systems behave beyond simple demonstrations.

Areas I explore include:

- Multi-agent workflows and state transitions
- LLM routing and provider abstraction
- Tool execution, guardrails, and structured outputs
- Local and hosted model inference
- Latency, throughput, concurrency, and resource utilization
- AI coding harnesses and automated development workflows

Architecture diagrams, benchmark methodology, and measured results will be published alongside the relevant project implementations.

## Engineering Results

I prefer measurable engineering improvements over unsupported performance claims.

For relevant projects, I aim to document:

| Measurement | What it demonstrates |
|---|---|
| Time to first token (TTFT) | Initial response latency |
| End-to-end latency | Time required to complete a request |
| Throughput | Requests or generated tokens processed over time |
| Concurrent request performance | Behavior under parallel workloads |
| Resource utilization | CPU, GPU, memory, and VRAM consumption |
| Cost per task | Estimated model and infrastructure cost |
| Task success rate | Whether the system completes the intended task |
| Reliability | Error rates, timeouts, and successful completion rates |

Actual results will be added when supported by recorded experiments, including the hardware, model, workload, and measurement methodology.
